# SPEC-008.3 — Per-persona model + thinkingLevel + fallback chain

## 1. Goal

- Bind each of the seven Gholas (`spec-writer`, `test-writer`, `implementer`,
  `validator`, `reviewer`, `steward`, `doc-scout`) to a specific
  primary model + ordered fallback chain via Oh My Pi's persona
  frontmatter, replacing the unspecified-model-defaulting behavior that
  shipped with slice-008.0.
- Use omp's in-frontmatter `model: string[]` fallback mechanism (verified
  in `pi-coding-agent/src/task/types.ts:189-201`) so each persona carries
  its own preference order, version-controlled with the persona file
  itself, with no `.omprc` drift surface.
- Honor Luci's Subscription Optimizer constraint: every link in every
  chain routes through a subscription, not an API key. The one exception
  Luci tolerates (Kimi) routes via the `kimi-code` subscription
  provider, not via the HF API-key path.
- Apply uniform `thinkingLevel: medium` per Luci's directive on this
  slice. The one model whose registered variants don't include `medium`
  (`gemini-3.1-pro`) is pinned to its closest-fit baked-in variant
  (`-high`) to honor the spirit of the directive.

## 2. Scope

In scope:

- YAML frontmatter edits to seven `.omp/agents/*.md` files: add
  `model: [...]` array and `thinkingLevel: medium` field. Persona body
  text unchanged (already updated in slice-008.1 for identity declaration).
- Verification by reading each file against §4 acceptance criteria — no
  test-writer step per project rule (markdown/config-only slice; see
  `~/.claude/projects/-home-fr-Code-Misc-pi/memory/feedback_test_scope.md`).

Not in scope:

- Editing `omp config set retry.fallbackChains.<persona>` global overrides.
  The in-frontmatter `model:` array is omp's per-persona mechanism and is
  sufficient on its own; the existing slice-007 `default` global chain
  remains as the safety net for any caller without a persona-pinned
  `model:` field.
- Changing the slice-007 default fallback chain in `omp config`. That
  chain (`opus → copilot/gpt-5 → antigravity/gemini-3.1-pro`) stays
  authoritative for non-persona callers.
- Persona body-text changes. Slice-008.1 already wired the `as_peer`
  identity declarations; this slice only touches frontmatter.

### 3.3 Uniform `thinkingLevel: medium` and the gemini exception

Luci's directive: `medium` for every Ghola. Verified compatibility per
runtime registry:

- `anthropic/claude-opus-4-7` — supports `minimal,low,medium,high,xhigh`. `medium` honored.
- `kimi-code/kimi-for-coding` — supports `minimal,low,medium,high`. `medium` honored.
- `openai-codex/gpt-5.5` — supports `low,medium,high,xhigh`. `medium` honored.
- `github-copilot/gpt-5.5` — supports `low,medium,high,xhigh`. `medium` honored.
- `google-antigravity/gemini-3.1-pro-high` — supports `low,high` ONLY. `medium` is not in the variant's permitted set. The slug-baked `-high` ensures the call still routes; omp's behavior on level mismatch is to use the variant's baked level rather than the persona's declared one. Documented trade-off, not a defect: gemini is the last-resort link only.

### 3.4 Why in-frontmatter array, not global config

omp 14.4.0 supports both: `model: ["a","b","c"]` in persona frontmatter,
AND `omp config set retry.fallbackChains.<persona> '[...]'` global
override. The in-frontmatter array is authoritative when present; the
global chain is the fallback for callers without `model:`.

In-frontmatter is preferred here because:

1. Version-controlled with the persona — every chain change goes through
   git review.
2. Self-contained per persona file — no `.omprc` drift surface; deleting
   a persona deletes its chain.
3. Coheres with slice-008.1's discipline of pinning persona contracts
   in the persona file itself, not in side-channel config.

The slice-007 `default` global chain stays unchanged in omp config and
serves as the safety net for any non-persona caller (e.g. a bare `omp`
invocation without `--task`).

## 4. Acceptance criteria

Each criterion is binary. All must pass before archive.

1. **Frontmatter present on all seven personas.** Every file in
   `.omp/agents/*.md` has both a `model: [...]` field and a
   `thinkingLevel: medium` field in its YAML frontmatter. (File-content
   read.)
2. **Per-persona chains match §3.2 mapping.** Each persona's `model:`
   array, in order, equals the row in §3.2 expanded to the full slug
   strings from §3.1. (File-content read.)
3. **All slugs are runtime-routable.** `omp --list-models="<slug>"`
   returns a non-empty match for every slug used across all seven
   personas. (Manual verification; one shell command per unique slug,
   five total.)
4. **Existing test suite preserved.** `bun run typecheck` and
   `bun run test` both pass with the same 238 pass / 15 skip / 0 fail
   baseline (frontmatter changes do not affect runtime tests).
5. **Persona body text unchanged from slice-008.1 state.** No edits to
   any text below the closing `---` of the frontmatter block. (Diff
   inspection.)
6. **A9 rollback drill remains feasible.** AGENTS.md still controls
   dispatch; per-persona model bindings do not couple Pi/omp dispatch
   in a way that prevents the slice-008.4 rollback. (Smoke: dispatch
   still works under both configs.)
